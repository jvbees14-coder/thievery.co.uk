Chapter 1

Noise flips bits

Every message a computer sends or stores is a row of ones and noughts. And every line or disc is a little noisy: interference, a scratch, a stray cosmic ray, and now and then a one arrives as a nought.

Sending again is one answer, if there's time to ask. A space probe billions of kilometres away, or a scratched CD, can't ask. The data has to carry enough spare information to repair itself.

Try it. Turn up the noise and send the bits again.

Chapter 2

One extra bit

The simplest check: add one bit to make the number of ones even. If an odd number arrives, something went wrong.

But it can't say which bit, so it can only ask for the message again. And two flips cancel out and slip through unnoticed.

Try it. Flip one bit, then two.

Chapter 3

Overlapping checks

In 1950 Richard Hamming, tired of his weekend jobs on a Bell Labs computer failing on errors, found a cleverer arrangement. Send four bits of data as seven: three check bits, each covering a different, overlapping group of the others.

Draw the groups as three circles. If one bit flips, exactly the circles that contain it fail their check, and every bit sits in a different combination of circles. So the failing circles point straight at the culprit, and the receiver flips it back.

Try it. Flip any one bit and watch the circles find it.

Chapter 4

Worth the extra bits

Hamming's code spends three bits to protect four, and it pays. If the line flips one bit in twenty, four bits sent plain arrive right only 81% of the time; sent as Hamming code, 96%.

Stronger codes built on the same idea are everywhere: in computer memory, mobile phones, QR codes, CDs and the radio links to spacecraft. They are why most data arrives whole over lines that are never quite clean.

Try it. Turn the noise up and compare the two lines.
