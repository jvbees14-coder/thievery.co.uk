Chapter 1

Sites keep a fingerprint

A website that does things properly never stores your password. It stores a of it: the result of running it through a function that scrambles it into a fixed-length string of bits.

The same password always gives the same hash, so the site can check you by hashing what you type and comparing. But there is no way to run the function backwards.

Change one letter and about half of the 256 bits flip, at random. A hash gives nothing away about how close a guess was.

Try it. Change one letter of the password and count the bits that light up. It is real SHA-256, worked out in your browser.

Chapter 2

Cracking is guessing

When a site is breached, attackers often get the list of hashes. They can't reverse them, so they guess: hash a candidate, compare, repeat.

Graphics cards are very good at this. One high-end card tries about 164 billion MD5 hashes a second, or 22 billion SHA-256 hashes. Every password of eight lower-case letters can be tried in under two seconds.

Attackers try the likely ones first: the most common passwords, then words, names and teams with numbers on the end. In a 2019 analysis of breached accounts, 23 million used "123456".

Try it. Make the password longer, then add capitals, digits and symbols, and see which helps more.

Chapter 3

Slow on purpose

MD5 and SHA-256 were built to be fast, which is exactly wrong for passwords. Password hashes such as bcrypt, scrypt and Argon2 are built to be slow, and their slowness can be turned up.

The same card manages about 184,000 bcrypt guesses a second at its lowest common setting. Each step up in its cost doubles the work, so at cost 12 it manages around 1,400. A user logging in waits a fraction of a second once; an attacker waits that long for every guess.

This site stores passwords with scrypt.

Try it. Keep the same password and switch from MD5 to bcrypt.

Chapter 4

Salt

If two people choose the same password, they get the same hash. An attacker who cracks one has cracked both, and can look hashes up in huge tables worked out in advance.

So sites add a : a random string stored next to each hash and mixed in before hashing. Same password, different salt, completely different hash. Every account has to be attacked on its own.

Try it. Switch the salt on and off.

Chapter 5

Length beats cleverness

Swapping letters for look-alike symbols doesn't help much: cracking tools try those swaps automatically. What helps is randomness and length.

Each random word picked from a list of 7,776 multiplies the search by 7,776. Four random words are about as strong as eight truly random characters, and far easier to remember; five are thousands of times stronger. The real answer is a password manager: a different long random password for every site, so one breach can't open the rest.
