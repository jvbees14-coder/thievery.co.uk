Chapter 1

Work out where it goes

To find a name in a list of a million, a computer could check them one by one. Far faster: decide where each name lives from the name itself. A hash function scrambles the name's letters into a big number, and the remainder after dividing by the number of buckets says which bucket to put it in.

To look a name up later, hash it again and look in that one bucket. However many names there are, it takes about the same time. This is a hash table, and it is behind almost every look-up a computer does.

Try it. Type a name and see which bucket it would be in.

Chapter 2

Collisions

Sooner or later two names land in the same bucket. It happens sooner than you'd think: with 16 buckets, five names have an even chance of a clash. It's the birthday paradox again.

So each bucket holds a short list, and a look-up checks the few names in it. As long as the lists stay short, it's still fast.

Try it. Add names and watch the red buckets, the ones holding more than one.

Chapter 3

Keep it roomy

Cram many names into few buckets and the lists grow long, and look-ups slow down. So hash tables watch how full they are, and when they pass a set level, often three quarters, they double the number of buckets and file everything again.

Doubling takes a moment, but it happens rarely enough that, on average, every look-up stays quick however large the table grows.

Try it. Add up to 60 names, with and without the table growing.

Chapter 4

A good scramble matters

Everything depends on the hash spreading names evenly. A poor one, filing by the first letter, say, might do for a handful of people, but real keys are often alike: photo-001, photo-002 and so on. By first letter, every one lands in the same bucket, and the table is no better than a list.

A good hash function makes similar inputs land far apart. Some attackers have even slowed web servers by sending keys chosen to collide, which is why many languages now mix a secret random value into their hashes.

Try it. Switch to a good hash and watch the photos spread out.

Sources and notes

The good hash in the scene is FNV-1a, a real and simple hash function, worked out in your browser. Each bucket keeps a list of its names, which is called separate chaining; some tables use other ways to handle collisions.
