Chapter 1

Text is numbers

A computer stores text as numbers, and numbers as bits: ones and noughts. Ordinary English letters each take one byte, eight bits, whether the letter is a common e or a rare z.

That is simple and wasteful. Compression is the art of storing the same thing in fewer bits, and getting every bit of it back.

Try it. Type anything. Each square is one bit; each colour is one character.

Chapter 2

Some letters are common

Characters don't turn up equally often. In English, e is about one letter in eight, and spaces are commoner still. Morse code already knew this: E is a single dot.

So the idea is to give common characters short codes and rare ones long codes. The catch is making the codes impossible to misread when they are run together with no gaps.

Chapter 3

Huffman's tree

In 1952 David Huffman, then a student at MIT, found the best way to do it. Write each character with its count. Join the two smallest into a pair, whose count is their total. Repeat until everything is in one tree.

Then read each character's code off the path from the top: 0 for every left turn, 1 for every right. Common characters join late and sit near the top, with short codes. And because no code is the start of another, a run of bits can only be read one way.

Try it. Step through the merges, or press Play.

Chapter 4

Fewer bits

Encode the text with the tree's codes and it shrinks, often to about half. To read it back, a program needs the tree as well, which costs a little space of its own, so very short texts don't really gain.

Huffman coding is still everywhere. It is one of the two halves of the method inside ZIP files, PNG images and the pages a web server sends, the other half replacing repeated phrases with short pointers back to their first appearance.

Chapter 5

What can't be squeezed

In 1948 Claude Shannon showed there is a floor. For a given mix of characters, its is the fewest bits per character any code of this kind can manage on average. Huffman's codes come within a whisker of it.

Truly random text has nothing to exploit: every letter is as likely as any other. And a file that has already been compressed looks random, which is why zipping a JPEG photo saves almost nothing.

Try it. Compare random letters with one letter repeated.
